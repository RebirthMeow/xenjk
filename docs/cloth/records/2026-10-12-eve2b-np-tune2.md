# eve2b_np skirt: run-start fly-up, found in the game input and fixed (2026-10-12)

Owner: "so even the tuned run has the skirt come up pretty high". Coordinator: in game the tuned skirt (old profile)
flies up and exposes her on run-start frames ~20-40 (t = 15.5 s + n/60 of the demo), the animated skirt does not.
Ripped Eve assets and everything derived (dumps, videos, sheets) stay in this folder. Nothing committed.

## Result
- **Cause: the felt forward velocity, not acceleration, legs or snapshot jitter.**
  - **Game input.** I dumped the exact solver input in game (new `r_clothDump`) and replayed it offline. The harness
    reproduces the game bit-for-bit (max diff 0.0 cm over 2,939 steps).
  - **Run-start motion.** Steps are regular 16/17 ms there, so this is not snapshot splitting. The pelvis goes
    186 -> 720 cm/s in ~0.12 s, then surges 570-870 cm/s per stride, with felt acceleration spikes up to ~11,000
    cm/s^2. At the same moment she turns (~280 deg/s yaw) and leans forward (pelvis tilt 3 -> 22 deg in 0.1 s).
  - **Not acceleration.** Lowering `maxFeltAcc` (800 -> 300 / 150) does nothing (17.8 -> 15.8 / 16.9 cm).
  - **Not the legs.** No collider is worse (20.1 cm).
  - **Velocity is the lever.** Felt linear velocity off: 2.2 cm. Angular off: 1.2 cm, but that kills the pirouette.
  - **The axis.** It is the per-axis scale on the pelvis-local **Z**: `linVelScaleZ` 0.2 gives 4.2 cm. X/Y 0.2 with
    Z 0.9 still gives 14.8.
  - **Why Z.** On this JKA-rigged skeleton the pelvis bone's local Z is the body's forward axis. Bind axes are X = up,
    Y = lateral, Z = forward/back (`frameFrom` uses the bone frame). The table's 0.7/0.7/0.9 was fitted with Z
    treated as vertical, so the run's forward velocity is felt at 0.9 instead of 0.7. Combined with the turn and the
    lean, that throws the back panel up.
  - **Not a blend artefact in the frame.** The solver Gram-Schmidts the frame, and the dumped pelvis matrices have row
    deviation 0.000 in this window. A separate session is reworking Ghoul2 blending; nothing here depends on it.
- **Fix.** `r_clothProfile 1` (default) = the old tuned set + `linVelScaleZ 0.2`. The old tuned set stays selectable
  as `r_clothProfile 2`; `0` = solver defaults.
- **Spin-aware cone: implemented in C, then parked (not needed for the acceptance window).** It is in
  `variant_spincone/` (params flareConeRest/flareSpinLo/Hi/OpenTime/CloseTime). It is not in the source tree, and the
  JS/SPEC were not changed. A static 45 deg cone would also calm runs and turns, but it halves the pirouette flare
  (rad 1.57 vs 1.9).
