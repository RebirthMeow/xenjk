# Record a human route

Run `tools/Start-HumanRouteRecording.ps1` in PowerShell, or:

```powershell
python tools/human_route_record.py
```

This starts a private Kejim CTF server and opens your game client with a
separate configuration directory. It uses the benchmark's movement settings
at normal real time. Your installed game files and normal key bindings are
not modified. The default team is red; `--team blue` starts on blue instead.

## Show a flag-to-flag run

1. Move to your home flag stand, empty-handed, and come to a complete stop.
   Close any game menu or console first (Escape or the console key).
2. Press **F8**. The console confirms that the recorder is armed.
3. Run normally. Your first movement or jump command starts the clock;
   enemy flag possession stops it automatically. No movement or Force input
   is generated by the recorder.
4. Press **F9** to stop an unfinished attempt; **F10** shows recorder status.
   Come back empty-handed to the stand and press F8 for another run. Each
   attempt gets a new file. Stopping a failed run keeps its evidence.

For the no-Force comparison, use ordinary tap jumps and avoid Force Speed
or held Force jumps. The recorder observes inputs and powers rather than
disabling them. If you demonstrate a different style, it will retain that
too; label it when asking for analysis. Consecutive positive jump commands
alone do not prove a Force-assisted jump.

The keys are only bound in the private client configuration. Equivalent
console commands are `cmd route_record arm`, `cmd route_record stop` and
`cmd route_record status`. You can change team through the normal Join Game
menu. Disconnecting, dying, changing team or ending the map closes an
incomplete recording instead of presenting it as a successful timed route.

## Where the evidence goes

The launcher prints the session directory:

```text
.codex-research/human-route-<UTC timestamp>/
  session.json                 settings, loaded binary binding, local server information
  build.sources.json           frozen source/binary manifest
  server/base/bot2-route/
    <recording>.csv            actual movement commands and native states
    <recording>.meta.json      map, physics, start conditions
    <recording>.summary.json   completion reason and timing
```

The CSV observes each authoritative Pmove call, with pre-movement,
post-movement and post-touch states. It preserves position, velocity, yaw,
grounding, command axes/buttons, jump latch, Force and power state. Timing
uses native server level time, not a stopwatch or an interpolated video.
Command times are also retained. File writes are opt-in and bounded; an
interrupted process can leave a partial file, which is not a complete run.

After recording, tell the assistant that the run is ready. No upload is
needed when working in this same workspace. The recording lets us compare
your route geometry, speed retained through corners, takeoff/landing states,
pit crossings and end-to-end timing against the bot's proposals. Recording
does not automatically train the bot or establish an executable bot policy.

The [2026-09-19 repairs](records/2026-09-19-review-repairs.md) corrected command

Demonstrations are optional evidence and potential prepared-plan inputs.
They do not substitute for the independent-search gate or block its progress.
The next diagnostic may use a recording's coarse corridor while generating
its own commands; unguided acceptance must remove that human guidance and
disable playback. See [the refined method](records/2026-09-19-refined-method.md).

To generate a report and portable route polyline:

```powershell
python tools/human_route_report.py "<absolute path to recording.csv>"
```

The report preserves original files and labels incomplete runs. The native
clock, stationary start and Force observations must be checked before
calling a run comparable to the bot benchmark. The recorder does not prove
that an arbitrary starting position is exactly the home stand.

To reconnect to an existing session or shut down its server:

```powershell
python tools/human_route_record.py --connect "<session directory>"
python tools/human_route_record.py --stop "<session directory>"
```

Shutdown preserves the recordings. Close the client normally. Only localhost
is used; do not share `session.json`, which contains the local rcon token.

## Developer binding

The launcher selects the latest complete `move-build-human-route-*` build,
or accepts `--build <directory>`. It verifies binary hashes and stages an
isolated copy. A recorded older binary remains bound to its source manifest
even if the working checkout later changes. Build new native code with:

```powershell
$humanBuild = '.codex-research/move-build-human-route-' + [DateTime]::UtcNow.ToString('yyyyMMddTHHmmssfffZ')
python tools/strafe_fixture_build.py --out $humanBuild
```

Commands require `bot_routeRecord 1` and `sv_cheats 1` on the practice
server; the recorder is off by default elsewhere. It records human players,
not bot control. Metadata plus the session manifest bind any analysis to
the actual map, physics and executable used.
