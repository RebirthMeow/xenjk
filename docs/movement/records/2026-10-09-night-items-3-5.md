### Item 3 follow-up: what slows the level-2 stand run (2026-10-09, diagnostic agent)

Same build (`nighttests-build-20261009-a`), same harness (`gate-20261009-a/run.py` `stand(level=2)` command, production
settings, library, class pins; the harness differs from `gate-20261005-e` only in the build path). One world a class
per arm (reps were identical), `time_ms`, all pass, 0 deaths; worlds in `.codex-research/gate-20261009-a/l2arms/`
(`arm.py`). Settings were set through `--set` and appear in each world's `start.cfg`.

| arm (set to) | 75 | 100 | 125 | 150 |
| --- | --- | --- | --- | --- |
| gate default (item 3) | 14,800 | 15,175 | 14,875 | 16,050 |
| A movement layer at stock (nine be_pmove switches) | 14,800 | 15,175 | 14,875 | 16,050 |
| B Force layer at stock (thirteen Force settings) | 14,800 | 15,325 | 14,725 | 15,850 |
| C every setting of `stock_force_profile.cfg` at stock | 14,800 | 15,325 | 14,725 | 15,850 |
| D `bot_moveWindowDefer 0`, `bot_moveWalkPoolFrameEnd 0`, `bot_movePathTables 0`, `bot_moveRerouteJoin 0`, `bot_movePlanEnclosed 0` | 10,650 | 11,950 | 10,550 | 9,000 |
| E `bot_moveWindowDefer 0`, `bot_moveWalkPoolFrameEnd 0` | 9,825 | 11,950 | 10,550 | 10,900 |
| 2026-10-05 gate (edgeroute build) | 10,775 | 10,975 | 11,025 | 9,125 |

Result: the competitive defaults (movement, Force, fights, stats) are NOT the cause; A, B and C reproduce the slow
times. The slowdown comes from Bot2 planner/timing defaults switched on between the 2026-10-05 gate (build sources
of 12dcb95c, 10-05 22:27) and now. Switching five of them off (D) puts every class back inside 13,000 ms; the
deferral pair alone (E: takeoff-window entry searches deferred, 10-06 cdede706, and the deferred searches' pool chunks
run at the frame's end, 10-06/10-07 9cc53399 and d1b05162) recovers 75/100/125 and most of 150 (10,900 against 9,000
in D, 9,125 on 10-05). The remaining 1.9 s at class 150 sits in the other three (route tables, reroute joins,
enclosed-goal skip), not split (arm budget of five spent). Not isolated to a single setting: WindowDefer versus
WalkPoolFrameEnd is untested. Mechanism not read from the route (no trace comparison made); it is a timing effect,
both settings change when a search runs and so which takeoff the stand run commits to (level-2 times are quantised).
Candidate-but-unmeasured: the 10-07 code changes without a switch (review fixes 4cfa1679, 74a3fa68, 3e539d1c) do not
appear to matter, since D recovers without touching them. The 10-05 build itself could not be rerun (its cgame sources
no longer match any checkout, so the bench refuses it). Row 2 and 4 misses were not rerun. Level-2 speed row: still
failing on the defaults; passes with arm D or E settings, which are not the shipped defaults. Nothing changed in
codemp/ and no gate was weakened. Deciding whether to keep these defaults (they were turned on for frame cost, owner
2026-10-06/07) is the owner's: they trade a 4-6 s slower level-2 stand run against frame time.
