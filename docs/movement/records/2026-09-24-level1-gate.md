## Row 3: the bot refused the flag

Both class-125 waiting runs are the leg's last 2.2 s (levels 14,300 and
14,925-16,400 from a 3,125 release). The bot reaches 792 u/s 713 units from
the flag, falls to 250 u/s on the ground and walks in, back-pedalling onto
the flag at 123 u/s. `bot_forecastTriggerLog 1` names the trigger that
refused the hops: `team_CTF_blueflag`, the objective, in 196 refusals.

The forecast refuses a touched trigger by contract, and `StraightArrives`
converts the refusal to `arrives` when `ArrivesAt` says the rollout reaches
the objective. `ArrivesAt` tested hull contact with the entity box, less the
8-unit `MOVE_ARRIVE_MARGIN`. The game does not pick an item up that way:
`G_TouchTriggers` takes an `ET_ITEM` when its box lies in the 40x40x52 range
about the origin and `BG_PlayerTouchesItem` holds - a region of -50..44,
+-36, +-36 about the item - at the end of the command. The refused hops passed
about 35 units from the flag's centre: a pickup by the game's rule, a miss by
the hull.

**Repair:** `ItemPickupAt` in `bot2_move.c` applies the game's item rule to
the same end-of-command positions `ArrivesAt` already projects. Non-item
objectives keep the hull test. On `gate-build-20260924-b`, one world each at
class 125: library **13,400 → 12,300 ms**, control 16,900 → 16,525 ms.

**The margin, corrected (build `d`).** Build `b` kept the 8-unit
`MOVE_ARRIVE_MARGIN` inside both boxes on every tested position. On build `c`
the class-150 library trip became 150 ms slower (14,075 → 14,225 ms): its tape's
last entry, the final straight hop, was refused. The flag's origin is its box's
bottom (2464, 5312, 1900.1), and that hop picked the flag up 28.8 units short
in y and 26.9 above it - inside the game's +-36 region, outside the margin in
both. The rollout's last frame is the forecast's own Pmove at the command end
the game tests (and the harness shows it exact), so it now takes the game's
rule with no margin; the projected frames after it, straight-line estimates,
keep the margin that fixed the 2026-09-23 flight over the flag. Build `d`
smoke: class 150 back to 14,075 ms with 10 of 10 entries hit, class 125
12,300, class 75 13,625, zero mismatches, floor 36/36. The build-`c` gate run
was stopped for this change (`gate-20260924-c/STOPPED.md`).

## Row 1: the mismatches come from the in-flight pre-search

No harness-on world ran between the seed gate (2026-09-22 16:42, zero
mismatches) and the build-`k` explorer (09-23 08:58: 722 of 792 armed worlds
with mismatches). Bisected on worktree builds, class-125 stand, harness on:

| Build | Mismatches |
| --- | ---: |
| `2d437c49` (rollout replay, search cache, budget 4 default) | 7 |
| `2d437c49`, `bot_forecastReplay=0` | 7 |
| `2d437c49`, `bot_moveSearchBudget=0` | **0** |
| `aadd17b8` | 6 |
| `gate-build-20260924-a`, `bot_moveSearchBudget=0` | **0** (13,400 ms, as with the budget on) |

Every mismatch has the same signature (diagnostic detail added in build `b`):
the live bot leaves the ground (`groundEntityNum` 1023, `PMF_JUMP_HELD` set,
7.3 units higher) where the harness predicted it grounded; the before-state
and command checks passed on that frame. **Cause: the taken pre-search never disarmed the harness.** A temporary audit
(`bot_moveChunkAudit`, build `audit-build-20260924-a`, since removed) compared
the bot's `gclient_t`, `gentity_t`, the live `pmove_t` and `level` byte for
byte across every chunk: no difference, so the chunk leaves no trace on the
live frame. The harness checks the before-state and command before the
searches run. A live straight search runs `StraightJudge`, which begins with
`ParityDisarm()`; a boundary served from the pre-search takes the judged set
through `SearchCacheTake` instead, which did not disarm. The commit then
re-issued the frame's command with the landing tap, and the harness, still
armed on the previous plan's horizon, compared that Pmove against a
prediction of the old plan: the live bot airborne, the prediction grounded.
The bot's own motion was never affected.

**Repair:** a successful `SearchCacheTake` disarms the harness, as the judge it
stands in for does. Build `c`: classes 75 and 125 with the budget on, zero
mismatches.
